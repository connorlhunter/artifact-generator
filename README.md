# Project Artifact Pipeline

Architecture documentation, Mermaid diagrams, this repository's coverage report, and TypeScript scripts for the portfolio-facing product artifacts in this repository.

## Start Here

```bash
bun install
bun run artifacts:sync-source
bun run docs:render:open -- <project-name>
bun run format:check
bun run test
bun run test:coverage
```

`artifacts:sync-source` pulls raw docs, diagrams, manifests, profile content, project markdown, icons, resume assets, and crypto images from private S3 before generation. S3 is the source of truth; the local source cache is disposable and should not be committed.
The docs preview renders to `dist/docs-preview/index.html`, then `docs:open` serves that bundle locally so linked diagram viewer pages, SVGs, and icons load like static assets.
The local preview server defaults to `127.0.0.1:41738`; set `DOCS_PREVIEW_HOST` or `DOCS_PREVIEW_PORT` to override it.
Formatting is handled by Prettier for supported source, test, config, HTML, JSON, and Markdown files.
Coverage is generated by Bun for the scripts and tests that exist in this repository, then rendered to `coverage/index.html`.

## Portfolio Publishing

This repository is the only place that generates and assembles portfolio artifacts. Project names are selector arguments for this generator; do not run artifact generation from each application repository.

This repo should be treated as a publishable artifact project for a portfolio site. It produces four artifact groups:

- Markdown docs preview HTML
- rendered Mermaid diagram SVGs
- HTML coverage report for this repository's scripts
- CloudFront-ready artifact and asset bundles

```text
S3 docs markdown             -> dist/docs-preview/
S3 Mermaid diagrams          -> rendered SVGs
coverage/index.html          -> dist/site-artifacts/coverage/ and projects/artifact-generator/coverage/
S3 manifests/profile/projects -> dist/site-artifacts/
S3 icons/resume/assets       -> dist/site-assets/
```

External application repositories own their source code and tests, but portfolio-facing docs, diagrams, coverage pages, manifests, icons, and resume assets are assembled through this generator project.

Publish this repo's generated artifacts as static web assets, not local filesystem paths. The selected deployment is private S3 behind CloudFront; detailed generated docs are published through the portfolio at `https://connorhunter.me`.

Docs and diagram render commands are run from this repository and require one project name to select the docs or diagrams to render:

```bash
bun run docs:render:open -- <project-name>
bun run diagrams:render -- <project-name>
```

Add GitHub source buttons to the docs preview by passing a repository name:

```bash
bun run docs:render:open -- <project-name> --github owner/repo
bun run docs:render:open -- cipher --github owner/repo --github-branch main
```

## Hooks

Git hooks are configured for local checks. The `.githooks` files are committed because Git does not version `.git/hooks`; keeping hooks in the repo makes the local checks reviewable, shareable, and reproducible across checkouts. `bun install` runs `scripts/git-hooks/setup-git-hooks.ts`, which configures `core.hooksPath` so Git runs the committed `.githooks` files instead of private local hook files. When the project is not inside a Git repo yet, prepare skips hook setup; run `bun run prepare` again after `git init`.

Both `pre-commit` and `pre-push` run:

```bash
bun run verify
```

`verify` runs:

```bash
bun run audit
bun run format:check
bun run lint
bun run typecheck
bun run test
```

`bun run audit` checks installed packages for known vulnerabilities and fails only for high or critical findings.

`bunfig.toml` also sets `minimumReleaseAge` to one week to reduce exposure to fresh supply chain attacks.

## S3 Source Inputs

The generator pulls raw source inputs from private S3 before rendering artifacts.
Configure these in `.env` locally:

```text
SOURCE_ARTIFACTS_BUCKET -> bucket containing docs, diagrams, manifests, profile, and projects
SOURCE_ARTIFACTS_PREFIX -> optional; leave blank when docs/ lives at bucket root
SOURCE_ASSETS_BUCKET    -> bucket containing icons, resume, and crypto images
SOURCE_ASSETS_PREFIX    -> optional; leave blank when icons/ lives at bucket root
SOURCE_INPUT_CACHE_DIR  -> optional disposable cache path for synced S3 inputs
```

Generated bundles are published locally with `bun run artifacts:publish`:

```text
ARTIFACTS_BUCKET
ARTIFACTS_PREFIX
ARTIFACTS_CLOUDFRONT_DISTRIBUTION_ID
ASSETS_BUCKET
ASSETS_PREFIX
ASSETS_CLOUDFRONT_DISTRIBUTION_ID
```

Dependency pins are declared in `dependency-pins.json`, then synced into `package.json` overrides with `bun run deps:policy`. Release-age exclusions are declared in `dependency-release-age-excludes.json`, then synced into `bunfig.toml`. Keep exclusions rare, pinned, documented with a reason, and remove them after the package is older than one week. JSON does not allow comments, so the `reason` fields are the review trail.

Security audits can also be run explicitly:

```bash
bun run audit
```
